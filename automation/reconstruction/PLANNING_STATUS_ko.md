# 계산·홈 복귀 개선 (2026-11-06)

기존 `run_tidy_demo.sh --execute`에 적용됩니다. 병렬 탐색은 추가하지 않았습니다.

- 계산 단계 시작과 5초 간격 경과 시간, 물체/후보/각도, 실패 이유, 재탐색 내용을 터미널과 execution.log에 출력합니다. 실행 기록 폴더의 current_status.json에 현재 단계도 저장합니다.
- 실패 후보는 현재 시작 관절값, 실제 장애물/부착 물체/충돌 허용 설정/좌표 변환, 속도 비율, 입력 파일, 가상 배치와 예약 위치가 같은 경우 한 번의 배치 탐색 안에서 재사용합니다. 새 스캔에서는 다시 검사합니다. 탐색 시간 초과는 불가능 판정으로 기록하지 않습니다.
- 출발·목표 자세를 먼저 검사합니다. 놓기 외곽·배치 끝점 충돌을 운반 경로 탐색 전에 검사합니다. 접촉/들기/내려놓기/후퇴 경로 전체 검사는 유지됩니다.
- 패드 예약을 다시 작성했습니다. 실제 MoveIt에 등록된 placed_ 물체의 외곽과 좌표 변환을 읽고, 패드 전체를 2mm 격자로 탐색합니다. 기존 물체와 2mm 간격, 패드 가장자리 2mm 여유, 원본 점군의 볼록 외곽을 유지합니다. 단일·다중 물체 모두 같은 IK/공동 예약을 사용하고, 단일 물체는 최대 5개 대체 위치를 보존합니다. 탐색은 패드당 40초와 후보 수로 제한되며 실패는 수학적 불가능 증명이 아닙니다.
- 경로당 1초 탐색 후 경로 탐색 실패에만 최대 8초로 재시도합니다. 배치 탐색은 300개 후보 또는 180초가 지난 후보 종료 시점에서 중단합니다. 완성된 전체 경로 없이는 집지 않습니다.
- 기존 점유 때문에 놓기 후보를 확보하지 못하면 점유 물체와 패드를 표시하고 재스캔을 반복하지 않습니다. 점유 모델은 자동 삭제하지 않습니다. 실행 직전에 점유 모델 변경과 예약 충돌을 다시 확인하며, 실제 놓기 형상도 기존 점유와 대조합니다.
- 그 외 실행 전 놓기 외곽 예약 또는 전체 경로 검토 실패가 기록된 경우에만 최대 1회 새 듀얼 스캔을 합니다. 직전에 빈 컵/홈/정지 확인이 필요합니다. 집기 실행 중 실패, 부분 완료, Ctrl-C, 통신/센서 이상은 자동 재스캔하지 않습니다. `--max-rescans 0`으로 끌 수 있습니다.
- HOME 서비스와 검토용 홈 복귀 계획은 Pilz PTP를 먼저 사용합니다. 거부되면 OMPL RRTConnect로 대체합니다. 기존 ValidateSolution과 FineCollisionAdapter를 모두 유지했습니다. 속도/가속도 비율은 RViz 값을 사용합니다.
- Pilz 시작에 필요한 KDL 모듈을 연결했습니다. HOME은 감사된 관절 각도를 직접 목표로 주므로 새 Cartesian IK 결과로 홈 각도를 정하지 않습니다. 기존 Python 면/축 IK와 캘리브레이션은 유지됩니다.
- 검증은 모의 안전 분기 테스트와 실제 계획 서비스의 계획 전용 요청입니다. 전체 물리 사이클 성공이나 속도 향상 배수는 아직 측정하지 않았습니다.

## 시작 시 빈 패드 초기화

사용자 확인에 따라 새 전체 시연/스캔 사이클은 패드 5·6을 빈 상태로 초기화합니다. HOME/스캔 전에 `placed_pad_5_*`, `placed_pad_6_*` 이전 모델만 삭제하고 장면을 재조회합니다. 삭제 전 장면과 결과를 보관합니다. 부착 물체가 있으면 중단하며 실행 도중/부분 완료 재개/계획 하위 명령에서는 초기화하지 않습니다.
