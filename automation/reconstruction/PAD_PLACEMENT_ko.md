# 같은 패드에 여러 물체 놓기

초록색은 전부 왼쪽 ID5, 회색/빨간색은 오른쪽 ID6에 배정한다.
첫 집기 전에 같은 패드로 갈 모든 물체의 배치를 공동 계산한다. 첫 물체를 패드 중앙에 고정하지 않는다.

`pad_packing.py`는 실제 점군의 평면 볼록 외곽을 사용한다. 패드 가장자리 2mm, 물체 사이 2mm를 유지한다. 크기를 줄이거나 쌓지 않는다. 배치 후보는 2mm 간격으로 검색한다. 검색 실패는 수학적 불가능 판정이 아니다.

배치 입력 JSON에는 pad_id, pad_center_table_m, diameter_m, objects가 필요하다. objects의 각 개별 ID 아래 cloud_file, placement_origin_table_m, placement_rotation을 넣는다. 회전 행렬은 실제 놓을 자세의 물체 회전이며 생략하면 단위행렬이다. 현재 촬영 자세와 놓는 자세가 다르면 반드시 회전을 계산해야 한다.

먼저 `pad_packing.py 입력.json placement_plan.json`으로 전체 예약을 만든다. 이후 각 실행에서 동일한 계획 파일을 `verified_place_left.py --placement-plan 계획절대경로 --placement-object 개별ID --pad 5 --inclined 세션절대경로`로 전달한다. 사전 확인 후 --execute를 붙인다. 세션 안의 placement_plan.json도 자동으로 읽는다. 기존 단일 물체 호출은 유지된다. 이전의 다른 일괄 실행 스크립트에 이 인자가 자동으로 전파되지는 않는다.

실행기는 실제 IK로 계산한 놓는 점군 외곽을 다른 예약/완료 물체와 다시 비교한다. 카메라 점검은 다음 놓을 영역을 확인하며 패드 전체가 비어 있어야 한다는 조건을 적용하지 않는다. 완료한 물체는 별도 충돌 ID와 실제 엔코더 기반 예상 위치로 저장한다. 패드 보정값이 달라지거나 같은 ID를 중복 실행하면 중단한다.

계획 파일의 완료 목록은 물체를 사람이 치웠다고 자동 초기화하지 않는다. 새 배치는 새 계획 파일로 시작한다. 실행 후 장면/물체가 바뀌면 재관측이 필요하다.

검증: 기하 검사 및 기존 검사 총 17개 통과. 모터 동작 및 두 물체 연속 놓기 실물 시험은 수행하지 않았다.
