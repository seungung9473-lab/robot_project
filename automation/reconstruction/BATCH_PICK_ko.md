# 전체 물체 사전 계획과 순차 실행

첫 집기 전에 요청한 모든 물체의 순서, 접촉면/턴테이블 각도, 접근, 접촉, 전체 들어 올리기, 운반, 놓기, 빈 컵 후퇴, 초기 홈으로 돌아오는 경로를 검사한다. 먼저 놓은 물체를 다음 단계의 가상 장애물로 추가하고, 그 물체를 턴테이블 장애물 목록에서 제거한다. 모든 단계가 통과한 완전한 순서가 없으면 집기를 시작하지 않는다.

`plan_pick_batch.py`는 기본적으로 모터·펌프 명령을 보내지 않는다. MoveIt 장면만 잠시 변경하고 검사 후 복구한다. `--execute`를 붙여야 완전한 배치 계획을 실행한다. 이미 완료된 물체는 `completed_placements.json`을 기준으로 제외한다.

```bash
source /opt/ros/jazzy/setup.bash
source ~/robot_ws/install/setup.bash
export ROS_DOMAIN_ID=73
python3 '/home/seungung9473/문서/ChatGPT/라파 대회/reconstruction/plan_pick_batch.py' '/새로운/스캔/세션' --objects object_1 object_2
```

계획 결과는 세션의 `batch_날짜_식별자/batch_plan.json`이다. `all_stages_ready: true`여야 실행 가능하다. 실행까지 하려면 위 명령에 `--execute`를 추가한다. 또는 다음처럼 저장된 완전한 계획을 실행한다.

```bash
python3 '/home/seungung9473/문서/ChatGPT/라파 대회/reconstruction/execute_pick_batch.py' '/세션/batch_날짜_식별자/batch_plan.json' --execute
```

실행 전 로봇은 홈이어야 한다. 신선한 엔코더와 압력, 턴테이블 영점, 모델/보정/리미트/실행 코드의 해시, 스캔 유효시간을 확인한다. 파일 또는 영점이 바뀌면 전체 계획부터 다시 해야 한다. 물체를 사람이 옮겼다면 새 스캔이 필요하다.

동일 패드에 여러 물체를 요청하면 먼저 `plan_batch_pad.py`로 전체 놓기 위치를 예약한다. 예약이 실패하면 첫 물체도 집지 않는다. 기존 예약은 `--pad-plan /경로/계획.json`으로 지정할 수 있다. 쌓기는 하지 않는다.

접근과 운반의 검토된 궤적을 저장한다. 실제 출발/목표 관절값 오차가 0.25도 이내이고 RViz 속도·가속도 비율이 동일하면 현재 장면에서 궤적을 다시 충돌 확인한 뒤 재사용한다. 흡착 재시도나 엔코더 차이로 조건이 달라지면 해당 동작은 실제 자세로 다시 계획한다. 따라서 모든 실행 중 계산을 없애는 기능은 아니다.

접촉/흡착/들어 올리기는 실제 엔코더와 압력에 의존한다. 진공 기준은 -300이며 실패 또는 피드백 이상 시 다음 물체로 자동 진행하지 않는다. 물체를 잡은 상태라면 자동 흡착 해제를 하지 않는다. 회전 후 영상 확인, 표면 재맞춤, 접촉점 재선택은 하지 않는다. 각 단계 전 놓기 패드만 회전 전에 확인한다.

단계 사이 홈 복귀는 기존 동작을 유지한다. 다음 단계 시작 전에는 앞 단계의 엔코더 기반 놓기 위치가 사전 계획과 3mm/1도 이내인지 확인한다. 이 값은 실물의 미끄러짐을 카메라로 검증한 값이 아니다.

검증 범위: 전체 순서 탐색/중간 실패 시 실행 차단/가상 놓기 장애물 전달/대체 각도 탐색/탐색 예산 제한/속도·자세가 바뀐 궤적 재사용 차단을 포함한 자동 검사 24개 통과. 새 배치 실행기의 연속 실물 동작은 아직 검증하지 않았다.

실환경 읽기 검증에서는 `/soarm4/rviz_scaling` 서비스가 응답하지 않아 모든 후보가 실행 불가로 종료됐다. 모터·펌프 명령은 보내지 않았다. RViz/해당 서비스가 동작한 상태에서 새 스캔으로 전체 실물 시험이 필요하다.
