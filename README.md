# table_clear — SO-ARM 날짜 분류 시연

공유 브랜치: `TUMST_test`. 자연어 또는 고정 실행 명령으로 등록된 턴테이블 위 물체를 스캔하고, 날짜에 따라 폐기 위치·패드5·패드6으로 분류합니다. 음성 입력은 아직 포함되지 않습니다.

## 받기

새 작업공간을 만드는 경우:

```bash
git clone --branch TUMST_test --single-branch https://github.com/seungung9473-lab/robot_project.git ~/robot_ws
cd ~/robot_ws
```

이미 이 저장소를 사용하는 경우, 로컬 변경을 정리한 뒤 해당 작업공간에서 `git switch TUMST_test`와 `git pull --ff-only origin TUMST_test`로 갱신합니다. 현재 코드는 여러 경로에서 `~/robot_ws`를 사용하므로 이 디렉터리 이름을 유지하세요.

## 설치와 빌드

기본 환경은 Ubuntu24.04 / ROS2 Jazzy입니다. ROS, MoveIt, RealSense SDK/ROS 드라이버, colcon, rosdep가 필요합니다. ROS 저장소와 rosdep 초기 설정을 먼저 마친 환경에서:

```bash
cd ~/robot_ws
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src --ignore-src -r -y --skip-keys ament_python
colcon build --base-paths src --symlink-install
source install/setup.bash
export ROS_DOMAIN_ID=73
```

### 별도 설치가 필요한 항목

Git에는 모델 가중치, Python 가상환경, API 키, 실험 원본을 넣지 않습니다. 저장소를 받기만 하면 GPU 추론까지 바로 준비되는 구성은 아닙니다.

- SAM2: 공식 설치 안내 https://github.com/facebookresearch/sam2 를 따라 CUDA 사용 가능한 PyTorch와 SAM2를 설치합니다. Python환경 위치는 `automation/reconstruction/.sam2_gpu/`, 가중치는 `automation/reconstruction/checkpoints/sam2.1_hiera_tiny.pt`입니다. SAM2.1 Hiera Tiny 설정을 사용합니다.
- CUDA Python 환경에서 ROS Python 패키지와 `numpy`, `scipy`, `yaml`, `cv2`, `PIL`, `serial`, `zxingcpp`를 사용할 수 있어야 합니다. ROS 패키지를 함께 쓰는 가상환경은 `--system-site-packages` 구성이 필요할 수 있습니다. `zxingcpp`의 pip 배포 이름은 `zxing-cpp`입니다. `run_sort.sh`, 자연어 진입점, ROS 실행 진입점은 실제 실행 시 CUDA Python을 선택합니다.
- 데스크탑 시연은 `sam2_gpu_config.json`의 CUDA/FP32 설정을 유지합니다. CUDA가 없는 친구 장비에서 이 GPU 시연 경로가 동작한다고 보장하지 않습니다.
- Gemini 키는 환경변수 `GOOGLE_API_KEY`/`GEMINI_API_KEY` 또는 개인 설정 `~/.config/soarm4/gemini.json`을 사용합니다. 코드에 키를 적지 않습니다. `python3 automation/er2/check_connection.py --setup-key` 명령은 키를 가려서 입력받아 개인 설정에 저장하고 텍스트 API 연결 시험을 수행합니다.

## 실행

### 안내만 확인 — 장치·API 실행 없음

```bash
cd ~/robot_ws
./run_sort.sh
SOARM_DEMO_BACKEND="$HOME/robot_ws" ./run_tidy_demo.sh "테이블 정리해"
```

기본 백엔드는 현재 `robot_ws`입니다. 인접한 `robot_ws_mybranch`의 코드를 자동으로 선택하지 않습니다. 다른 백엔드는 `SOARM_DEMO_BACKEND`, 다른 CUDA Python은 `SOARM_SAM2_PYTHON`으로 명시할 수 있습니다. 실제 실행에서 CUDA가 없으면 이동 전에 중단하며 CPU로 대체하지 않습니다.

### 실제 분류

대회장 데스크탑에서 장비 전원을 연결하고 흡착컵을 비운 뒤 준비 명령을 실행합니다.

```bash
cd ~/robot_ws
./run_tidy_demo.sh
```

이 명령은 준비 스크립트 `run_prepare_demo.sh`를 실행해 장치·CUDA·Gemini 키 설정을 확인하고, 제어 드라이버와 카메라 두 대, RViz를 시작합니다. 기존 제어 시스템이 있으면 재사용합니다. 펌프를 끄고 압력 영점을 맞춘 뒤 새 압력값이 0 근처인지 확인합니다. 정지 상태의 컬러·깊이 촬영을 확인하고, 저장된 턴테이블 영점이 유효하면 현재 자세에서 로봇팔과 턴테이블 토크를 켭니다. `준비 완료`가 표시된 뒤 패드 5·6을 비우고 물체를 올린 다음 출력된 분류 명령을 실행합니다. 실제 분류를 시작할 때도 HOME 이동과 스캔 전에 빈 컵의 압력 영점을 다시 확인합니다.

준비가 끝나면 데스크탑에 **TUMST ARM 시연 모니터**도 열립니다. 실제 분류를 시작하면 촬영 각도별 두 카메라 이미지, Gemini 검출과 SAM2 마스크, 날짜·배치 결과, 경로 검사·집기 진행과 누적 시간이 갱신됩니다. 복원 데이터가 나오면 오른쪽 화면에 점군과 흡착 후보가 표시되고, 안전점검을 통과한 배치 계획이 저장되면 현재 물체의 검증된 TCP 경로가 파란색으로 표시됩니다. 마스킹 이후에는 왼쪽에 CAM 1 실시간 컬러 영상이 표시됩니다. F11로 전체 화면을 전환합니다. 창을 닫았으면 ROS Jazzy 환경을 불러온 터미널에서 `/usr/bin/python3 automation/reconstruction/demo_monitor.py`로 다시 열 수 있습니다. 기존 실행 결과는 같은 명령에 `--run <실행 기록 폴더>`를 붙여 볼 수 있습니다.

아래는 드라이버만 직접 기동하는 방법입니다.

서보·진공·턴테이블 제어 브리지, 두 카메라, MoveIt와 작업대 장면을 먼저 준비해야 합니다. 진입점은 드라이버를 자동 기동하지 않습니다. 준비된 드라이버가 없을 때는 별도 터미널에서 한 번만 다음을 실행합니다.

```bash
source /opt/ros/jazzy/setup.bash
source ~/robot_ws/install/setup.bash
export ROS_DOMAIN_ID=73
ros2 launch soarm_pipeline desktop_ready.launch.py allow_execution:=true
```

이 준비 명령은 제어용 드라이버·카메라·MoveIt·RViz를 기동합니다. 토크ON·HOME·집기·회전 목표는 보내지 않습니다. 진공 드라이버의 초기화는 펌프/밸브 OFF와 압력 영점을 수행하므로 물체를 들고 있는 중에는 사용하지 않습니다. 기존 드라이버가 이미 실행 중이면 중복 기동하지 않습니다. 이후 다른 터미널에서 아래 분류 명령을 실행합니다. 장치 연결/빈 컵 확인은 Gemini 해석 전에 수행하여 미연결 상태에서 API를 먼저 호출하지 않습니다.
 장치 연결 및 보정 관련 준비법은 각 `src/` 패키지의 안내를 확인하세요.

```bash
cd ~/robot_ws
# 고정 날짜 분류: HOME, 회전 스캔, 인식, 경로 검증, 집기·분류
./run_sort.sh --execute

# 또는 자연어 지시 해석을 포함하는 시연
SOARM_DEMO_BACKEND="$HOME/robot_ws" ./run_tidy_demo.sh "테이블 정리해" --execute
```

`--execute`는 실제 모터·턴테이블·펌프 동작을 요청합니다. 두 명령을 동시에 실행하지 않습니다. 장치·압력·시작 자세가 확인되지 않거나 경로가 실패하면 중단합니다. 이 배포 정리에서는 모터를 작동시키거나 실제 완주를 확인하지 않았습니다.

## 2026-11-08 mybranch 통합 — 데스크탑 프로필

원격 `mybranch`의 `c50090d`를 병합했습니다. 노트북 CPU 고정 경로는 CUDA/FP32로 교체했습니다. 새 전체 실행 전 이전 턴테이블·패드 스캔 모델과 표시를 정리하고, 고정 작업대와 과거 기록은 유지합니다. 부착 물체가 있으면 초기화를 거부합니다.

서보 토크ON 전 현재 위치 hold 목표를 읽어 확인하는 보호, URDF/엔코더 범위 안의 제한된 미세 보정과 상태 보고, TCP/반복 오차 시험 도구를 포함합니다. 미세 보정 파라미터를 제외한 기존 영점·게인·관절 범위·압력·속도·카메라/작업대 형상과 폐기 관절 목표는 보존했습니다. J3 적분 시험 도구는 통합됐지만 실행하거나 모터 설정을 바꾸지 않았습니다. 엔코더 기반 TCP 오차는 실제 팁을 외부에서 실측한 정확도와 다릅니다.

### GPU 설정 검증

RTX5060, PyTorch2.11.0+cu128 / CUDA12.8에서 저장된 실제 듀얼12방향 영상24장과 물체3개(마스크72개)로 비교했습니다. FP32 유지, 이미지 특징24회만 계산해 물체 간 공유, 선택적 리뷰 JPG 출력은 기본 생략합니다.

- 배치1: 워밍업 후 2회 중앙값 약2.10초.
- 배치2: 약2.15초, 마스크72개 모두 배치1과 픽셀 단위 일치.
- 이 자료에서는 배치2가 빠르지 않아 기본 배치1을 유지했습니다. 더 큰 배치나 BF16을 무조건 활성화하지 않습니다.
- 위 시간은 영상 읽기·PNG 저장을 포함한 SAM2 단계입니다. 모델 로딩 약0.77초는 별도이며, 실제 촬영·복원·Gemini·경로 계산·로봇 이동 시간은 포함하지 않습니다. 전체 시연 시간으로 해석하면 안 됩니다.
- CPU 요청 및 CUDA 부재 시 추론 전에 중단하는 경로를 검사했습니다. 실제 로봇 구동과 유료 API 호출은 이번 통합 검사에 포함하지 않았습니다.

이 PC의 가상환경/가중치는 기존 검증된 로컬 자산을 링크해 사용합니다. 링크나 가중치는 Git으로 공유하지 않으므로 다른 PC에서는 같은 위치에 별도 설치해야 합니다.

## USB 연결과 카메라 프레임

`desktop_ready.launch.py`는 D415 USB 속도를 확인해 두 대 모두 USB3이면640×480 15fps, USB2가 포함되면 같은 해상도의6fps를 선택하고 이유를 출력합니다. USB2에서15fps를 사용했을 때 깊이 영상 손상/정렬 깊이 누락이 실제 발생했고, 6fps에서 내부행렬 일치·정지촬영3회·듀얼12방향 스캔과0도 복귀를 확인했습니다. 원시 카메라 점군 출력은 전체 분류에서 사용하지 않아 데스크탑 준비 경로에서 생략합니다. 컬러·깊이·정렬깊이는 유지합니다.

프레임 수를 명시하려면 준비 명령에 `camera_fps:=6` 또는 `camera_fps:=15`를 추가할 수 있습니다. USB 허브가 실제로 연결 해제되는 문제는 프레임 설정만으로 해결된다고 보장하지 않습니다. 서보·ESP32·OpenRB가 동시에 사라지면 커널 USB 연결 해제 기록과 허브/케이블/전원을 먼저 확인합니다. 제어 모드는 끊긴 동작을 자동 재개하지 않습니다.


### 연속 분류 동작 (2026-11-08)

전체 시연의 새 배치 계획은 물체마다 HOME으로 복귀하지 않습니다. 패드에 내려놓고 흡착 해제를 확인한 뒤 컵을 30mm 연속 후퇴하여 대기하고, 팔이 정지한 상태에서 다음 물체의 턴테이블 각도로 회전합니다. 다음 집기 경로는 직전 대기 자세를 출발점으로 미리 검토합니다. 폐기 단계는 등록된 폐기 위치에서 해제 후 대기합니다. 첫 전체 스캔 전 HOME은 유지합니다.

접촉 접근은 한 궤적으로 이동하며, 엔코더로 계산한 접촉면 법선 거리가 5mm 이하가 되는 첫 피드백에서 펌프 ON을 비동기로 요청합니다. 펌프를 켜기 위한 중간 정지는 없습니다. 실제 트리거 거리는 피드백 주기의 영향을 받으며 실행 기록에 남습니다. 접촉 후 흡착 확인, 이송 중 압력 감시와 충돌 검사는 유지합니다.

상승·내려놓기·빈 컵 후퇴는 10mm씩 정지하던 분할을 제거하고 각각 하나의 고정 방향 직선 궤적으로 실행합니다. 중간 위치와 속도·가속도 제한은 계속 검사합니다. RViz 기본 속도 비율은 0.80, 가속도 비율은 기존 0.40이며 물리적 관절/서보 한계는 변경하지 않습니다.

턴테이블 회전 전에는 빈 컵과 실제 대기 자세를 확인하고, 아직 남은 물체의 전체 회전 범위를 둘러싸는 보수적인 실린더와 팔의 충돌을 검사합니다. 대기 위치가 안전하지 않으면 회전하지 않고 중단합니다. 기존에 생성한 계획은 새 코드와 달라 재계획해야 합니다. 변경 후 소프트웨어 테스트·빌드와 RViz 비율 읽기 확인을 수행했으며, 실제 80% 동작 시간/정확도는 별도 실험 전까지 검증값으로 주장하지 않습니다.


### 마지막 HOME과 시연 기록

전체 배치는 각 물체 사이의 HOME을 생략하며, 모든 집기·해제·후퇴가 성공한 후 빈 컵 압력을 새로 확인하고 마지막에 한 번만 HOME으로 복귀합니다. 마지막 HOME까지 성공해야 전체 완료로 기록합니다. 중단/부분 실패에는 자동 HOME을 호출하지 않습니다. HOME은 기존 Pilz PTP 및 충돌 검사 경로를 사용합니다.

대회 데모는 터미널에 **지능형 로봇대회 시연**으로 표시됩니다. 기존 50회 평가의 자동 등록을 종료했으며, 새 시연의 실행 결과는 일반 실행 기록에 저장됩니다.

성공·실패·사용자 중단을 모두 포함하며 실패 회차를 지우거나 다시 성공으로 바꾸지 않습니다. JSON 원본과 회차별 CSV, 집계 JSON, 읽기용 요약을 보존합니다. 로그상 전체 완료와 사람이 확인한 물리적 성공은 구분합니다. 첫 기록은 로그상 3/3 완료·320.9818초이며 마지막 HOME 추가 전 실행입니다. 향후 회차는 시작 시 Git 커밋을 저장하므로 코드 변경에 따른 실험 조건을 구분할 수 있습니다. 첫 회차의 과거 커밋을 현재 커밋으로 추정하지 않습니다. 평가 활성화 설정·원본 데이터·CSV는 로컬 실험 데이터로 Git 업로드에서 제외합니다.
